# Finland native-owner detection

The production application uses grouped mined V2 `OrderFilled` subscriptions. It does not start `run_leader_monitor`, a REST trade/activity loop, the old provisional pending source, or a REST fallback after a source failure. Inventory, position sizing, market metadata, risk management, and order reconciliation are separate read paths.

Every active owner defaults to Alchemy mined logs. `detection.native.traders` accepts explicit wallet policies (`mode: mined|pending`, `provider: alchemy|infura`, `on_budget_exhausted: mined|pause`, `enabled: true|false`). Configuration writes retain the existing expected-revision checks and `restart_required=true`, `live_applied=false` behavior. New discovery members stay paused as `awaiting_restart`; they are not task-activation eligible until a new process acknowledges their source. Retired owners are removed from dispatch immediately.

Each mined filter contains both approved V2 exchanges, the V2 topic0, and owner addresses only in topic2. Groups contain at most 100 wallets and cover the complete configured roster without truncation. An empty roster creates no subscription. Native taker summary logs also belong to topic2: their side, shares, notional and fee come from their own log. Topic3 never creates an inverted counterparty signal.

One Alchemy connection multiplexes the mined groups. The shared ledger records estimated RPC and stream usage but imposes no local monthly/daily quotas, reserves, pending-data caps, per-second throttles, or plan/baseline approval gates. Legacy quota settings remain accepted for compatibility and are inert; snapshots report `limits_enforced=false`, `limit=null`, and `remaining=null`. Provider-side restrictions still apply. A separate receive task captures each message's original receipt before recovery or enrichment can delay processing. The frame limit is 1 MB, transport queue is 16, and application buffer is 1024 messages. Overflow fails visibly. The transport disables redirects, environment proxies and URL logging. At most three explicit session attempts are made. Connection and active-leader state changes are logged as `native_detection_state`. Risk and reconciliation keep their independent lifecycle.

Infura standing logs are unavailable because per-block billing is not implemented; a boolean verification flag cannot bypass this. Such traders report `unsupported_stream_billing` while supported owners can continue. Infura may serve bounded recovery RPC reads through the same shared ledger. No third provider, paid upgrade, automatic plan change, or direct trade endpoint is introduced.

After subscription acknowledgment, recovery reads a bounded inclusive interval with an 8-block overlap, in 10-block chunks, at most 5000 blocks. If downtime exceeds that window, detection automatically resumes from the recent overlap after validating it. The skipped historical interval is reported as `native_detection_recovery_gap`; it is not claimed as recovered and is not replayed into orders. Existing source identities and tombstones remain intact. A failed recovery leaves the previous checkpoint unchanged. Prior included block identities within the selected window are compared with canonical headers and replaced inclusions are tombstoned. Recovery occurs on connection establishment; it is not a periodic trade polling loop. Historical recovery and bootstrap-buffered old data never create fresh copy entries.

The local SQLite ledger retains action identity, inclusion identity, transaction reorg identity, checkpoints, removal tombstones and trader source state. It does not prune evidence when its configured capacity is full. Source admission happens before the existing per-follower/task dispatcher: a crash can under-copy but cannot replay an admitted source action into a second copy. Existing follower/task reservations and order claims remain authoritative for execution. Re-inclusion, including a changed log index after a transaction moves blocks, is evidence-only. No automatic compensating trade is performed.

`GET /v1/detection` includes `traders`, or `null` while the native source is uncomposed. Each state carries desired mode, effective mode, provider, exhaustion policy, enabled flag, degradation reason, optional last observed receipt time, and restart requirement. Bot telemetry remains session-local; this state is not advertised as cursor-replayable telemetry. Durable shared raw evidence is provided by the optional separate pmrecon publisher. When it is disabled, source composition still runs with a discarding sink, so raw observations are neither persisted nor shared; pending evaluation, which requires a durable sink, refuses to compose without one.

Pending-mode preferences retain independent mined coverage. The phase2 runtime reports `mined` with `pending_disabled`; it never sends a pending event into execution. Enabling a future pending evaluator requires its own bounded read-only admission and protocol reconciliation integration.

Deterministic tests use fake transports and temporary SQLite databases. They do not validate an Alchemy/Infura account's current plan, a production endpoint, real subscription delivery, live execution, or the old MILP/Nautilus pipeline. Deployment requires environment-specific verification.
